# 问题与修复记录（Bug fixes / change log)

## 2026-09-10（首次对外发布前的加固）

目标：让"完全没配过环境"的同学也能自己装起来，并且出问题时能自己定位。

### 1. 一键环境自检：`doctor.py` + `诊断.bat`（新）

- 逐项检查：Python 版本/位数/是否在 `.venv`、`tkinter`、11 个依赖包、主程序模块导入、
  识别设备（CUDA/CPU）、语音模型缓存、网络连通性（HuggingFace / hf-mirror /
  DeepSeek / Google）、API key 来源、翻译实测、麦克风与内录设备、保存目录可写性。
- 输出用 `[OK] / [!!] / [XX]` 分级，最后给一句话结论；遇到问题让使用者**整段复制**发回即可。
- `--quick` 跳过联网与翻译实测。

### 2. 安装脚本加固：`install.bat`（新，`安装同声传译.bat` 变成它的同义入口）

- 安装前探测可用 Python：`python` → `py -3`，并校验 **≥3.10**；找不到时直接给出
  python.org 下载链接和"记得勾 Add python.exe to PATH"的提示。
- 依赖安装失败时**自动换清华 PyPI 镜像重试一次**（大陆网络常见）。
- 预下载**实际会用到**的模型：`base.en`（实时默认）+ `small.en`（文件模式默认），
  可选 `large-v3-turbo`（用 `choice` 询问，25 秒无输入自动跳过）。
  此前只下载 `small.en`，导致第一次实时使用仍要临时下载 `base.en`。
- 直连 HuggingFace 失败自动改用 `hf-mirror.com` 重试（`setup_models.py`）。
- 之前模型下载步骤**没有检查退出码**，失败也照样打印 "Done"；现在失败会明确报出来。
- 安装结束自动跑一次 `doctor.py --quick` 作为验收，并可直接启动程序。

### 3. 启动脚本加固：`run.bat`（新，`启动同声传译.bat` 变成它的同义入口）

- 检测不到 `.venv` 时，询问是否**直接调用安装脚本**，装完继续启动（原来只在一闪而过的
  窗口里提示 "run setup first"）。
- 程序异常退出时提示运行 `诊断.bat` 并保留窗口，不再让错误信息随窗口关闭消失。

### 4. API key 设置向导：`设置API密钥.bat`（新）

- 提示粘贴 `sk-...`，写入项目内 `.env`（`.env` 已在 `.gitignore` 中，不会进仓库）。

### 5. `requirements.txt` 显式声明 `pillow`

- 图形界面用 PIL 加载 mascot/贴图，此前只是**间接**依赖（经 `python-pptx` 带入）；
  一旦依赖关系变化，GUI 会静默丢掉头像，现显式声明。

### 6. 首次使用体验的几处修补

- 语音模型加载失败时，若错误像是**联网下载失败**（Connection/timeout/SSL/代理等），
  额外打印一条可照做的提示（先跑自检、大陆网络用 `HF_ENDPOINT=https://hf-mirror.com`、
  或先跑安装脚本把模型下好）。
- `--file` 指向不存在的文件时，原来会抛出 `WhisperModel` 的堆栈；现在直接提示"找不到音频文件"
  并给出用法示例。
- `Pipeline._open_stream()`：`last_err` 在"一个候选设备都没有"时未初始化，会抛
  `NameError` 掩盖真实原因，现已给出默认原因文本。

### 7. 文档

## 2026-08-30

本次修复均集中在 `tongchuan.py`，未改动其它模块；行为仅在异常/检出场景下变化，正常路径不变。

### 1. 转写 Markdown 保存偶发 `PermissionError`

- **现象**：图形界面控制台抛出
  `PermissionError: [Errno 13] ... transcripts\同声传译_*.md`，对应这一条结果没有写进转写稿；
  程序本身仍继续运行，只是 Tk 回调被异常打断、频繁刷屏。
- **原因**：转写文件名只精确到秒。同一秒内启动多个会话/实例会生成**同名文件**，Windows 下多个进程争抢
  同一文件句柄，追加写入会被拒；或文件被编辑器 / 杀软短暂占用时也会拒绝写入。
- **修复**（`MarkdownLogger`）：
  - 文件名加入**毫秒 + 进程号**，彻底避免同名冲突。
  - 创建与追加写入都加入**重试**（最多 6 次、每次间隔 0.1s）；追加在重试后仍失败时仅记录到控制台，
    不再向 GUI 回调抛出异常。

### 2. 系统声音（内录）句子检出率偏低

- **现象**：麦克风模式基本正常，切换到“系统声音”后很多句子识别不到，表现为整句被漏掉。
- **原因**：内录采集是 **48kHz**（部分设备 44.1kHz），但项目使用 **silero VAD（16kHz 模型）**；
  `faster_whisper.vad.get_speech_timestamps` 只会用 `sampling_rate` 换算时长，**不会对音频重采样**，
  于是 48k 数据被原样喂给 16k 模型，导致说话概率失真、成段人声检不出来。
- **复现**：同一段英语语音，按 16k 喂入 VAD 检出 **2 段**，按 48k 喂入只检出 **1 段**（且起始被明显推迟）。
- **修复**（`Pipeline` / `Segmenter`）：
  - 分段器和 ASR 统一在 **16kHz** 下工作，避免再用设备采样率。
  - 系统内录每块音频在送入分段器**之前先重采样到 16k**。
  - 内录立体声**合并为单声道**（原先仅取左声道 `arr[:, 0]`，会漏掉内容在右/中间声道的声音）。

### 3. 转写保存仍偶发 PermissionError：外部云同步/杀软锁文件

- **现象**：即使在文件名加入毫秒+进程号后，实时运行仍偶发 `PermissionError`，被拒的是刚创建、内容可正常追加的文件。
- **排查**：目录/文件 ACL 正常、非只读、不在 OneDrive 下；另开进程能正常追加；本进程连续追加 300 次 0 失败。
- **根因（强烈怀疑）**：目录内出现大量百度网盘同步产物 `*.baiduyun.uploading.cfg`，云同步/杀软在写入瞬间**短暂锁住文件**，
  导致这类偶发 `PermissionError`——即锁来自外部进程，而非程序自身逻辑或文件名冲突。
- **修复**（`MarkdownLogger`）：
  - 改为**指数退避重试**（最多 14 次、间隔从 0.05s 放大到约 1s，累计约 3s），扛过短暂扫描/同步锁。
  - 主文件持续被锁时**自动降级写入 `*.bak.md`**，内容不丢并明确提示。
  - 已将 `*.baiduyun.uploading.cfg` 加入 `.gitignore`。

### 4. 结束提示转写稿位置

- 控制台模式结束时打印：`[已结束] 转写稿保存位置：<path>`；若产生备用稿还会提示。
- 图形界面关闭窗口时也在日志面板与控制台打印位置。

### 5. 控制台 / GUI 日志配色

- 终端日志统一灰色（ANSI `\033[90m`），仅 `EN:`/`ZH:` 字幕行保持原色；重定向/管道时自动关闭颜色避免乱码。
- GUI 日志面板非字幕行同样用灰色，中英字幕行保持原色。

### 6. 命令行可调参数（带默认值）

- `--max-seg`（默认 4.0s）：分段上限，调大可减少长句被切断（延迟更高）。
- `--min-silence`（默认 0.5s）：判定一句结束的静音时长。
- `--min-words`（默认 3）：少于该词数的识别片段会被跳过；设 `1` 表示不过滤。
- 同步把控制台模式接上这些参数，GUI 仍用自身默认。四个 `命令行_*.bat` 脚本顶部提供可编辑的同名变量。

### 7. 异常中断 / 断电时的数据持久性（fsync）

- **问题**：实时转写是逐行 `open → write → close`，数据只进入**系统页缓存**；进程被杀 / 崩溃无碍
  （操作系统会异步落盘），但**突然断电 / 硬关机**时，最后写入的内容可能还留在页缓存（内存）中而丢失。
  此前没有任何 `fsync`，因此**无法保证**断电时保存。
- **修复**：
  - `MarkdownLogger` 每次写入（含标题、每条结果、以及主文件与 `.bak` 备用文件）后调用 `flush()` + `os.fsync()`
    （Windows 即 `FlushFileBuffers`），`append()` 返回时该内容已落到物理磁盘。
  - 文件模式 `--file --save` 的最终保存同样加 `flush()` + `os.fsync()`。
- **性能**：转写按句追加（约每几秒一次），单次 fsync 开销可忽略，实时识别 / 翻译几乎不受影响。
- **备注**：`--save-audio` 的 WAV 仍是流式写入、未逐帧 fsync；如需断电也不丢，可另加周期性 fsync。

### 8. 命令行 `.bat` 脚本在中文 Windows 下报“不是内部或外部命令”

- **现象**：双击 `命令行_*.bat` 会先刷出一堆乱码的“不是内部或外部命令”，随后 python 报
  `error: argument --model: expected one argument`。
- **原因**：`.bat` 被保存为 **UTF-8**（含中文注释/提示），而中文 Windows 的 `cmd` 默认按 **GBK** 读取，
  中文行字节被误读、命令被拆碎，导致 `set "MODEL=..."` 未执行、`--model` 丢了参数值。
- **修复**：把 4 个 `命令行_*.bat` 全部改成**纯 ASCII**（提示改英文），任何代码页下都能正确解析；
  仍保留 `chcp 65001` + `PYTHONUTF8=1`，程序自身的中文输出照常显示。
