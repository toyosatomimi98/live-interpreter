# 问题与修复记录（Bug fixes / change log)

## 2026-08-30

本次修复均集中在 `tongchuan.py`，未改动其它模块；行为仅在异常/检出场景下变化，正常路径不变。

### 1. 转写 Markdown 保存偶发 `PermissionError`

- **现象**：图形界面控制台抛出
  `PermissionError: [Errno 13] ... transcripts\同声传译_*.md`，对应这一条结果没有写进转写稿；
  程序本身仍继续运行，只是 Tk 回调被异常打断、频繁刷屏。
- **原因**：转写文件名只精确到秒。同一秒内启动多个会话/实例会生成**同名文件**，Windows 下多个进程争抢
  同一文件句柄，追加写入会被拒；或文件被编辑器 / 杀软短暂占用时也会拒绝写入。
- **修复**（`MarkdownLogger`）：
  - 文件名加入**毫秒 + 进程号**，彻底避免同名冲突。
  - 创建与追加写入都加入**重试**（最多 6 次、每次间隔 0.1s）；追加在重试后仍失败时仅记录到控制台，
    不再向 GUI 回调抛出异常。

### 2. 系统声音（内录）句子检出率偏低

- **现象**：麦克风模式基本正常，切换到“系统声音”后很多句子识别不到，表现为整句被漏掉。
- **原因**：内录采集是 **48kHz**（部分设备 44.1kHz），但项目使用 **silero VAD（16kHz 模型）**；
  `faster_whisper.vad.get_speech_timestamps` 只会用 `sampling_rate` 换算时长，**不会对音频重采样**，
  于是 48k 数据被原样喂给 16k 模型，导致说话概率失真、成段人声检不出来。
- **复现**：同一段英语语音，按 16k 喂入 VAD 检出 **2 段**，按 48k 喂入只检出 **1 段**（且起始被明显推迟）。
- **修复**（`Pipeline` / `Segmenter`）：
  - 分段器和 ASR 统一在 **16kHz** 下工作，避免再用设备采样率。
  - 系统内录每块音频在送入分段器**之前先重采样到 16k**。
  - 内录立体声**合并为单声道**（原先仅取左声道 `arr[:, 0]`，会漏掉内容在右/中间声道的声音）。

> 备注：`selftest.py` 在本次改动后除第 8 项“翻译片段时不输出‘请提供…’”偶发抖动外全部通过；
> 该项依赖翻译接口对不完整片段的即时回答，重跑即恢复，与本次代码改动无关。
